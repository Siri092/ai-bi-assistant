# Mini AI Business Intelligence Assistant

A lightweight AI-assisted Business Intelligence application that allows users to ask natural-language questions about sales data and receive answers calculated from a SQLite database.

The application uses Python, FastAPI, SQLite, SQL, and a browser-based interface. It combines natural-language question interpretation with predefined analytics queries to provide structured answers and supporting figures.

## 1. Project Overview

**Objective:** Build a Mini AI Business Intelligence Assistant that enables business users to retrieve useful insights from sales transaction data using natural-language questions.

The application imports the supplied CSV dataset into SQLite, interprets user questions, executes predefined analytics queries, and returns the calculated results through a web interface and REST API.

## 2. Technologies Used

- **Programming language:** Python
- **Backend framework:** FastAPI
- **Database:** SQLite
- **Query language:** SQL
- **Frontend:** HTML, CSS, JavaScript
- **Testing framework:** Pytest
- **AI integration:** Local intent interpretation with optional OpenAI-powered intent classification
- **Version control:** Git and GitHub

## 3. Features

- Imports the supplied sales CSV file into a SQLite database at application startup.
- Answers questions about total revenue, top-performing products, monthly revenue trends, regional performance, and revenue comparisons.
- Provides a simple browser-based interface for entering questions and viewing results.
- Exposes a REST API through FastAPI.
- Returns structured results and supporting figures.
- Uses predefined analytics queries instead of executing arbitrary SQL generated by an LLM.
- Supports local question interpretation without requiring an OpenAI API key.
- Handles unsupported questions and invalid month-comparison inputs with helpful messages.
- Includes automated tests for important analytics and question-handling behavior.

## 4. Supported Questions

The application supports the following five analytics tasks:

1. **Total revenue:** What is the total revenue?
2. **Top product:** Which product generated the highest revenue?
3. **Monthly revenue trend:** What is the monthly revenue trend?
4. **Top region:** Which region generated the highest sales?
5. **Monthly comparison:** How did revenue change between two months?

Example month-comparison question:

`Compare revenue between 2026-01 and 2026-02`

Month comparisons require months in `YYYY-MM` format.

## 5. Dataset and Revenue Calculation

The application uses the supplied sales dataset:

`data/sales_data.csv`

The dataset includes transaction dates, products, categories, regions, sales channels, quantities, unit prices, discounts, and transaction statuses.

### Revenue formula

Revenue is calculated as:

`(quantity * unit_price) - discount_amount`

### Data-quality rules

The application includes only transactions that meet the following criteria for revenue analytics:

- Transaction status is `Completed`.
- Quantity is greater than zero.
- Unit price and discount values are valid, non-missing, non-negative numeric values.

Returned transactions are excluded from revenue metrics. Records with missing unit prices are retained in the database for traceability but excluded from revenue calculations.

These are explicit assumptions for this assessment. In a production environment, missing prices and other data-quality issues should be reviewed with the business or data owner.

## 6. Application Architecture

The application follows a simple, modular architecture.

**Request flow:**

Browser interface → FastAPI `/ask` endpoint → Question interpreter → Whitelisted analytics intent → Predefined SQL query → SQLite database → Structured response

### Main components

- **Frontend (`static/index.html`):** Provides the user interface for entering questions and viewing answers.
- **Backend (`main.py`):** Exposes the API and coordinates question interpretation and analytics.
- **Database module (`database.py`):** Loads the CSV data into SQLite.
- **Analytics module (`analytics.py`):** Implements database-backed calculations for the supported analytics tasks.
- **Question interpreter (`interpreter.py`):** Maps natural-language questions to supported analytics intents and relevant parameters.
- **Tests (`tests/test_analytics.py`):** Verify important analytics and question-handling behavior.

### AI integration and query safety

The application can use optional OpenAI integration to classify a question into a supported analytics intent. When local interpretation is used, the application recognizes supported question patterns.

The analytics layer executes predefined database queries rather than arbitrary SQL generated by the language model. This limits the operations available to the question interpreter and helps prevent destructive database operations.

## 8. Setup and Installation (Windows)

### Prerequisites

- Python 3.11 or newer, provided the installed dependencies support your Python version.
- Git (optional if downloading the repository as a ZIP file).
- A code editor such as Visual Studio Code.

### Step 1: Open the project

Clone the repository:

```powershell
git clone https://github.com/Siri092/ai-bi-assistant.git
cd ai-bi-assistant
```

Alternatively, download the repository as a ZIP file, extract it, and open the project folder in Visual Studio Code.

### Step 2: Create a virtual environment

```powershell
python -m venv .venv
```

Activate it:

```powershell
.venv\Scripts\activate
```

### Step 3: Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### Step 4: Configure optional AI integration

If you want to use OpenAI-powered intent classification, configure the API key according to the application's environment-variable configuration and the provided `.env.example` file.

Do not commit API keys or other secrets to GitHub.

The application is designed to support local question interpretation when optional AI integration is not configured.

### Step 5: Start the application

Run the following command from the project root:

```powershell
uvicorn main:app --reload
```

### Step 6: Open the application

- **Web interface:** http://127.0.0.1:8000
- **API documentation:** http://127.0.0.1:8000/docs

The application should be running in the terminal while you use the interface.

## 10. API Usage

The application provides the following endpoint:

`POST /ask`

Example JSON request:

```json
{
  "question": "What is the total revenue?"
}
```

The response includes the interpreted question intent, the answer, supporting data, and the interpretation method, according to the application's response schema.

You can test the endpoint through the FastAPI interactive documentation at:

http://127.0.0.1:8000/docs

## 12. Error Handling and Reliability

The application is designed to:

- Return helpful responses for unsupported question types.
- Validate the expected month format for comparisons.
- Use predefined analytics operations for database calculations.
- Keep the supported analytics scope explicit.
- Provide structured results that can be inspected through the API.

The application is an assessment prototype and has not been presented as a production-hardened system.

## 13. Known Limitations

- The local interpreter recognizes a limited range of natural-language patterns.
- Month comparisons require explicit `YYYY-MM` values.
- Analytics are limited to the supplied sales dataset and predefined query types.
- Production deployment, authentication, and comprehensive operational monitoring are outside the current scope.
- Optional AI interpretation depends on the configured integration and service availability.
